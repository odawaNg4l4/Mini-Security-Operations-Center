Endpoint Enrollment – Windows Server Agent

Project Objective

The objective of this phase was to connect a Windows Server virtual machine to the Wazuh SIEM as a monitored endpoint. This enables the Wazuh Manager to collect and analyze security events generated by the Windows operating system.

Objective of Endpoint Enrollment

The purpose of installing the Wazuh Agent on Windows Server is to:

Collect Windows security logs.
Monitor authentication events.
Monitor system activity.
Send logs securely to the Wazuh Manager.
Allow security analysts to detect suspicious activity from the Wazuh Dashboard.
Verifying the Wazuh Manager

Before installing any agents, the Wazuh Manager was verified to ensure it was ready to accept endpoint connections.

The following command was executed on the Ubuntu Server:

sudo ss -tulpn | grep wazuh
Command Explanation
sudo executes the command with administrative privileges.
ss displays active network sockets.
-t displays TCP sockets.
-u displays UDP sockets.
-l displays listening ports.
-p shows the process using each port.
-n displays numeric addresses and port numbers.
grep wazuh filters the output to display only Wazuh services.
Output
tcp LISTEN 0 128 0.0.0.0:1515 users:(("wazuh-authd",pid=1181,fd=6))
tcp LISTEN 0 128 0.0.0.0:1514 users:(("wazuh-remoted",pid=1291,fd=4))
Interpretation

The output confirmed that:

wazuh-authd was listening on port 1515, allowing new agents to register.
wazuh-remoted was listening on port 1514, allowing registered agents to send security logs.

This confirmed that the Wazuh Manager was ready to receive endpoints.

Determining the Wazuh Server IP Address

The Ubuntu Server IP address was obtained using:

hostname -I

Output:

192.168.100.15

This address is required because every Wazuh Agent must know the IP address of the Wazuh Manager in order to establish communication.

Starting the Agent Service

After installation, the Windows Wazuh Agent service was started using:

NET START Wazuh
Command Explanation
NET is a Windows administration command.
START instructs Windows to start a service.
Wazuh is the name of the installed Windows service.

Successful output indicated that the Wazuh Agent service had started correctly.

Initial Enrollment Issue

Although the service was running successfully, the Windows endpoint did not appear under the Agents section of the Wazuh Dashboard.

A structured troubleshooting process was initiated.

Troubleshooting Process
Step 1 – Verify Agent Service

The following command confirmed that the Wazuh Agent service was running:

Get-Service Wazuh

Result:

Status : Running
Step 2 – Verify Network Connectivity

The Windows Server successfully communicated with the Ubuntu Server using:

ping 192.168.100.15

Connectivity between the endpoint and Wazuh Manager was confirmed.

Step 3 – Verify Server Address

The Ubuntu Server IP was confirmed using:

hostname -I

Result:

192.168.100.15
Step 4 – Inspect Agent Configuration

The agent configuration file was opened using:

Get-Content "C:\Program Files (x86)\ossec-agent\ossec.conf"

During inspection, the following configuration was identified:

<address>198.168.100.15</address>
Root Cause

A typographical error had been introduced during agent configuration.

Configured Address:

198.168.100.15

Actual Wazuh Manager:

192.168.100.15

Because of this incorrect IP address, the Windows Agent attempted to communicate with a non-existent server and therefore never completed registration.

Resolution

The agent configuration file was edited.

Incorrect:

<address>198.168.100.15</address>

Correct:

<address>192.168.100.15</address>

The Wazuh Agent service was then restarted.

Stop the service:

NET STOP Wazuh

Start the service:

NET START Wazuh

Restarting the service forced the agent to reload the corrected configuration.

Successful Enrollment

After correcting the manager IP address and restarting the agent service, the Windows Server successfully connected to the Wazuh Manager.

The endpoint appeared in the Wazuh Dashboard under Agents, confirming successful enrollment.

Lessons Learned

Several important lessons were learned during this stage of the project:

A running service does not necessarily indicate a correctly configured service.
Verifying IP addresses is one of the first steps when troubleshooting connectivity issues.
Reading configuration files is often more effective than repeatedly reinstalling software.
Security engineers should follow an evidence-based troubleshooting process rather than making assumptions.
Small configuration errors, such as an incorrect IP address, can prevent endpoint enrollment even when all services appear to be functioning normally.
