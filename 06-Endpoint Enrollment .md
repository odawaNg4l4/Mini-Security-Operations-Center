# Endpoint Enrollment – Windows Server Agent

## Project Objective

The objective of this phase was to connect a **Windows Server** virtual machine to the **Wazuh SIEM** as a monitored endpoint. This enables the Wazuh Manager to collect and analyse security events generated by the Windows operating system.

---

# Lab Environment

| Component | Role |
|-----------|------|
| VirtualBox | Virtualisation platform hosting all virtual machines |
| Ubuntu Server | Wazuh Server (Manager, Indexer, Dashboard, Filebeat) |
| Windows Server | Endpoint monitored by Wazuh |
| Kali Linux | Attack machine (to be connected later) |

# Objective of Endpoint Enrollment

The purpose of installing the Wazuh Agent on the Windows Server is to:

- Collect Windows security logs.
- Monitor authentication events.
- Monitor system activity.
- Send logs securely to the Wazuh Manager.
- Enable security analysts to detect suspicious activity through the Wazuh Dashboard.

# Verifying the Wazuh Manager

Before installing any agents, the Wazuh Manager was verified to ensure it was ready to accept endpoint connections.

The following command was executed on the Ubuntu Server:

```bash
sudo ss -tulpn | grep wazuh
```

## Command Explanation

| Option | Description |
|--------|-------------|
| `sudo` | Executes the command with administrative privileges |
| `ss` | Displays active network sockets |
| `-t` | Displays TCP sockets |
| `-u` | Displays UDP sockets |
| `-l` | Displays listening ports |
| `-p` | Shows the process using each port |
| `-n` | Displays numeric IP addresses and port numbers |
| `grep wazuh` | Filters the output to display only Wazuh services |

### Output

```text
tcp LISTEN 0 128 0.0.0.0:1515 users:(("wazuh-authd",pid=1181,fd=6))
tcp LISTEN 0 128 0.0.0.0:1514 users:(("wazuh-remoted",pid=1291,fd=4))
```

### Interpretation

The output confirmed that:

- `wazuh-authd` was listening on **port 1515**, allowing new agents to register.
- `wazuh-remoted` was listening on **port 1514**, allowing registered agents to send security logs.

This confirmed that the Wazuh Manager was ready to receive endpoint connections.

# Determining the Wazuh Server IP Address

The Ubuntu Server IP address was obtained using:

```bash
hostname -I
```

### Output

```text
192.168.100.15
```

This address is required because every Wazuh Agent must know the IP address of the Wazuh Manager in order to establish communication.

# Deploying the Windows Agent

From the Wazuh Dashboard:

```text
Dashboard
    │
    ▼
Agents
    │
    ▼
Deploy New Agent
```

The following settings were selected:

| Setting | Value |
|---------|-------|
| Operating System | Windows |
| Server Address | 192.168.100.15 |
| Agent Name | Windows-Server |
| Group | default |

The generated installation command was executed on the Windows Server.

# Starting the Agent Service

After installation, the Windows Wazuh Agent service was started using:

```cmd
NET START Wazuh
```

## Command Explanation

| Command | Description |
|----------|-------------|
| `NET` | Windows administration command |
| `START` | Starts a Windows service |
| `Wazuh` | Name of the installed Wazuh Agent service |

A successful response indicated that the service had started correctly.

# Initial Enrollment Issue

Although the Wazuh Agent service was running successfully, the Windows endpoint did **not** appear under the **Agents** section of the Wazuh Dashboard.

A structured troubleshooting process was initiated.

---

# Troubleshooting Process

## Step 1 – Verify the Agent Service

The following PowerShell command confirmed that the Wazuh Agent service was running:

```powershell
Get-Service Wazuh
```

### Result

```text
Status : Running
```

---

## Step 2 – Verify Network Connectivity

The Windows Server successfully communicated with the Ubuntu Server using:

```cmd
ping 192.168.100.15
```

This confirmed that network connectivity between the endpoint and the Wazuh Manager was functioning correctly.

---

## Step 3 – Verify the Wazuh Manager IP Address

The Ubuntu Server IP address was confirmed using:

```bash
hostname -I
```

### Result

```text
192.168.100.15
```

---

## Step 4 – Inspect the Agent Configuration

The Wazuh Agent configuration file was inspected using:

```powershell
Get-Content "C:\Program Files (x86)\ossec-agent\ossec.conf"
```

During inspection, the following configuration was identified:

```xml
<address>198.168.100.15</address>
```

---

# Root Cause Analysis

A typographical error had been introduced during the agent configuration.

### Incorrect Configuration

```xml
<address>198.168.100.15</address>
```

### Correct Configuration

```xml
<address>192.168.100.15</address>
```

Because of the incorrect IP address, the Windows Agent attempted to communicate with a non-existent server and was therefore unable to complete registration with the Wazuh Manager.

---

# Resolution

The agent configuration file was edited to use the correct manager IP address.

### Incorrect

```xml
<address>198.168.100.15</address>
```

### Correct

```xml
<address>192.168.100.15</address>
```

The Wazuh Agent service was then restarted.

Stop the service:

```cmd
NET STOP Wazuh
```

Start the service:

```cmd
NET START Wazuh
```

Restarting the service forced the agent to reload the updated configuration.

---

# Successful Enrollment

After correcting the manager IP address and restarting the Wazuh Agent service, the Windows Server successfully connected to the Wazuh Manager.

The endpoint appeared in the **Agents** section of the Wazuh Dashboard, confirming successful enrollment.

# Lessons Learned

This phase reinforced several important operational and troubleshooting principles:

- A running service does not necessarily indicate a correctly configured service.
- Verifying IP addresses should be one of the first steps when troubleshooting connectivity issues.
- Reading configuration files is often more effective than repeatedly reinstalling software.
- Security engineers should follow an evidence-based troubleshooting process rather than relying on assumptions.
- Small configuration errors, such as an incorrect IP address, can prevent endpoint enrollment even when all services appear to be functioning correctly.

# Real-World Relevance

Endpoint onboarding is a fundamental task in Security Operations Centre (SOC) environments. SIEM platforms such as Wazuh rely on properly configured agents to collect telemetry from servers and workstations. Even minor configuration mistakes, such as an incorrect management server address, can prevent endpoints from reporting security events and create monitoring blind spots. Developing a structured troubleshooting methodology ensures that security engineers can quickly identify root causes, restore visibility, and maintain comprehensive monitoring across enterprise environments.
